# شاهد — نسخه به‌روزشده

## تغییرات جدید

### فیلتر کلمه
- فعال‌کردن: `/gm تنظیم فیلتر(کلمه)`
- لغو فیلتر: `/gm لغو فیلتر(کلمه)`
- پیام‌های کاربران عادی که حاوی کلمه فیلترشده باشند حذف می‌شوند و یک اخطار عادی می‌گیرند.
- اخطارهای فیلتر با اخطارهای دستی مشترک‌اند؛ `/gm لغو اخطار` روی کاربر همچنان کار می‌کند.
- بررسی فیلتر برای متن و کپشن رسانه‌ها انجام می‌شود.

### آرشیو پیام
در گروه روی پیام موردنظر Reply کنید و بفرستید:
`/archive`

بات پیام را به کانالی که در `ARCHIVE_CHANNEL_ID` تنظیم کرده‌اید Forward می‌کند.

## تنظیمات Cloudflare
در Worker → Settings → Variables and Secrets این موارد را تنظیم کنید:

- `BOT_TOKEN` (Secret): توکن BotFather
- `WEBHOOK_SECRET` (Secret): یک مقدار تصادفی قوی فقط با حروف انگلیسی، اعداد، `_` و `-` (حداقل 32 کاراکتر)
- `ADMIN_IDS` (Variable): شناسه عددی ادمین‌ها، جداشده با کاما
- `ARCHIVE_CHANNEL_ID` (Variable): شناسه عددی کانال مقصد، معمولاً با `-100` شروع می‌شود

بات باید در گروه دسترسی حذف پیام و محدودکردن/بن کاربران داشته باشد و در کانال آرشیو Administrator باشد.

## نکته مهم Privacy Mode
برای اینکه فیلتر بتواند پیام‌های عادی کاربران را بررسی کند، بات باید پیام‌های عادی گروه را دریافت کند. بنابراین Privacy Mode روشن کافی نیست؛ در BotFather باید Group Privacy را خاموش کنید (Turn off) و سپس بات را در گروه نگه دارید/در صورت نیاز دوباره اضافه کنید. بدون این تغییر، بات معمولاً پیام‌های عادی کاربران را نمی‌بیند و فیلتر عمل نخواهد کرد.

## نصب
فایل `src/index.js` را جایگزین نسخه قبلی کنید و Deploy بزنید. اگر از GitHub integration استفاده می‌کنید، تغییرات را Commit کنید تا Cloudflare دوباره Deploy کند.


## امنیت وبهوک و حریم خصوصی

### محافظت در برابر جعل وبهوک
Worker اکنون فقط درخواست `POST` دارای هدر معتبر `X-Telegram-Bot-Api-Secret-Token` را می‌پذیرد. اگر `WEBHOOK_SECRET` در Cloudflare تنظیم نشده باشد، درخواست‌ها fail-closed می‌شوند. در Bot API نیز باید همین مقدار هنگام `setWebhook` ثبت شود؛ در غیر این صورت وبهوک کار نخواهد کرد.

1. در Cloudflare، مقدار `WEBHOOK_SECRET` را از نوع **Secret** اضافه کن.
2. برای ساخت مقدار تصادفی امن می‌توانی از یک password manager استفاده کنی. مقدار باید فقط شامل `A-Z`, `a-z`, `0-9`, `_`, `-` باشد و 32 تا 128 کاراکتر باشد.
3. وبهوک تلگرام را با همان مقدار تنظیم کن (جایگزین مقادیر نمونه کن):

```bash
curl -X POST "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://<YOUR-WORKER-URL>","secret_token":"<WEBHOOK_SECRET>"}'
```

توکن بات و secret را در GitHub، کد، پیام‌ها یا لاگ‌های عمومی قرار نده. اگر قبلاً توکن بات افشا شده، از BotFather آن را تعویض کن.

### چه چیزی ذخیره می‌شود؟
- متن/رسانه پیام‌های عادی گروه برای فیلتر بررسی می‌شود و در کد به KV یا دیتابیس نوشته نمی‌شود؛ بدنه درخواست و متن پیام‌ها نیز عمداً لاگ نمی‌شوند.
- قابلیت `/save` به‌صورت عمدی محتوای پیام انتخاب‌شده توسط ادمین را در KV ذخیره می‌کند تا بعداً با دستور ذخیره‌شده ارسال شود. اگر این قابلیت را نمی‌خواهی، باید حذفش کنیم یا از آن استفاده نکنی.
- در KV به‌جز پیام‌های ذخیره‌شده، نگه‌داری تنظیمات فیلتر، شمارنده اخطارها و یک درخواست موقت `/save` (حداکثر 10 دقیقه) لازم است.
- `/archive` پیام ریپلای‌شده را به کانال آرشیو **فوروارد** می‌کند؛ در نتیجه آن پیام در کانال مقصد باقی می‌ماند.
- این تضمین به معنی «هیچ‌جا ذخیره نمی‌شود» نیست: تلگرام پیام‌ها را در سرویس خودش نگه می‌دارد و Cloudflare/تلگرام ممکن است متادیتای عملیاتی داشته باشند. این Worker محتوای پیام‌های عادی را خودش ذخیره نمی‌کند؛ اما `/save` و `/archive` عمداً استثنا هستند.
